01. Reuse market-clock formatters

A date/time conversion currently constructs a new Intl.DateTimeFormat. Chart positioning and readouts repeat this across the points, on the server and during hydration.

Keep formatter instances in the existing market-hours module, keyed by the actual time zone and formatting options. These instances hold formatting rules only.

02. Send fewer chart-coordinate digits

SVG paths, pointer widths and guides serialize full floating-point coordinates. Most of those digits cannot affect what a person sees, but they recur across 1,620 points.

Round only display geometry: SVG coordinates to two decimal places and percentages to three. Derive hit widths from rounded cumulative edges so they still tile the plot exactly.

04. Start independent reads sooner

Root-loader parallelism already shipped. A few remaining page reads wait behind work whose result they do not need.

  • Overview: after resolving the owner reading, start account totals and freshness alongside chart reach and manual history.
  • Narrowed Holdings: start household and narrowed holdings reads together; current code waits for the household wave first.
  • Holdings editor: consider starting the current-position read alongside other reads once its identifiers are known.

These shorten the server’s critical path. They do not eliminate a browser round trip per database query. Measure query duration and pool contention before assigning a speed claim.

Preserve owner canonicalization, mandatory lock checks, shared masking decisions, and distinct household/narrowed query behavior. Attach rejection handling to work started early.

Keep what already works

Static caching is doing its job.

  • Hashed /assets/ responses are public, max-age=31536000, immutable. Repeat visits in the browser test transferred zero bytes for those assets.
  • The server negotiates Brotli and sets Vary: Accept-Encoding. Compression is already active.
  • Routed documents and data keep no-store. The ordinary HTTP cache for static files does not require storing financial pages in the service worker.
  • Routes already split, and server-only database/feed libraries are absent from the emitted client files. Initial route discovery loads small metadata, not every route’s code.
  • The font is already hashed, preloaded and metric-matched. Navigation preload and palette PNG icons are present in the examined revision.

Verified against installed @react-router/serve 7.18.4, compression 1.8.2, the fresh build and live response headers. Network requests still cross the deployed gate; browser cache hits avoid those requests.

References: HTTP cache freshness · React Router code splitting · ADR-0007.

Smaller follow-ups

  • Metadata freshness. The fixed manifest and favicon URLs currently return max-age=0 and support 304 validation. A short TTL for successful static responses, or a versioned favicon, can avoid some repeat requests. Keep documents, data, redirects and sw.js outside that rule.
  • Later worker registration. Register after initial load to avoid first-visit contention. The worker is only 2.8 KB raw and precaches nothing, so expected benefit is small; first-visit offline guidance becomes available later. Google’s guidance.
  • Passkey route coupling. Moving shared passkey predicates out of the Unlock route can also stop Settings from importing the Unlock display chunk. The ceiling is under 2.2 KB gzip of avoidable code, and often it is already cached.
  • Font range experiment. Inter is 48.3 KB and effectively incompressible. Restricting the variable font to the used weights may save bytes; the saving and visual equivalence have not been measured.

I would defer a framework rewrite, more tiny route chunks, global CSS splitting, and custom precompression infrastructure. Framework code dominates the existing client bundle, the full stylesheet is only 8 KB gzip, and current compression/caching already cover the main static-asset wins.
